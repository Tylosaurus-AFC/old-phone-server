# Maintenance audit — October 2026

Technical review of the public repository (code, tests, docs), done **without a phone**: every
result below comes from reading the code and from `tests/run.sh` on a Linux PC (x86_64,
Python 3.11, no network). Nothing here was checked on real hardware.

## Architecture (as found)

* **PC side** `tools/*.sh` (bash): install, deploy, backup/restore over adb (root) or SSH (no-root).
* **Root mode** `phone/*.sh` (Android `sh`/mksh + busybox): Debian in a chroot at `/data/debian`;
  `start.sh` at boot (Magisk `service.d`, init.rc or KingRoot hook) → `charge.sh` (watchdog every
  minute, charge limiter through sysfs) and `bot.sh` (bot supervisor with back-off).
* **No-root mode** `phone/noroot/*.sh` (Termux bash): Debian in proot-distro; Termux:Boot →
  `boot.sh` → `charge.sh` (watchdog; Android access through Shizuku/rish, Termux:API as fallback)
  and `bot.sh`; `guard.sh` runs as the `shell` user and reopens Termux if Android kills it. The
  charge limit is the phone maker's own feature: these scripts only read it.
* **Bot** `bot/` (Python, `requests`): Telegram long-polling, downloads with yt-dlp/gallery-dl,
  ffmpeg, optional MTProto uploads (Telethon), voice transcription, plugins in `extras/plugins/`.
  Shared health: `events.jsonl` (written by bot, `bot.sh`, `charge.sh`) and `heartbeat`
  (watchdog restarts a bot silent for 5 min).

Supervision already present: single-instance pid checks, exponential back-off (10 s → 10 min)
with a "ran > 120 s resets" rule, intentional-stop detection (143/137, `deploying`), heartbeat
for frozen processes, network wait before starting, Wi-Fi cycling after 5 min offline, orphan
bot kill, `BOT_ENABLED` latch against two phones with one token, log trimming, token scrubbed
from logs, owner-only/private-only commands, persistent download queue.

## To validate on a real phone

1. Deploy (`tools/deploy.sh` or `tools/noroot-deploy.sh`), check `/salud` and one link.
2. `/diagnostico`: the file arrives; read it and confirm no token, chat IDs, IPs or link paths.
3. Inside Debian: `/opt/bot/venv/bin/python3 /opt/bot/diag.py | head` works.
4. `/actualizar`: success message with versions; `/historial` shows `actualizacion`.
5. Rollback: pin an old yt-dlp, make the upgrade fail (e.g. temporarily point pip to an unreachable
   index with `PIP_INDEX_URL=http://127.0.0.1:9/` in the bot's environment) and check the old
   version is still installed and an `aviso` is logged.
6. Buttons: under a video press **MP3** and **Original**; `/help` shortcuts; `/cola` cancel. A
   non-owner pressing an owner button in a group must get nothing.
7. Backups: `tools/backup.sh` / `tools/noroot-backup.sh` now include `channels.json`, `likes.json`,
   `bot.db` when they exist; restore on a spare phone and check `/canal` and `/stats`.
8. PC tools on Windows (Git Bash) and Linux: `tools/install.sh check` with a correct `config.sh`;
   then with `ADB` pointing nowhere and with `PHONE_IP`/`USB_SERIAL` empty (expect the new messages).
   No-root: `printf 'TOKEN\n' | tools/noroot-bot.sh token` stores the token.
9. No-root: with `NET_HOSTS` unset nothing changes; with `NET_HOSTS="<router IP>"` and the router
   reachable, the bot starts.
